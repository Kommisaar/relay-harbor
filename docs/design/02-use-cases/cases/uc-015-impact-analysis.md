# UC-015 影响定位

> 状态：草稿
> 关联：FR-013、FR-010、NFR-002

## 目标

开发者对某一条目获得"变更后需要重新检查"的下游条目与任务清单。

## 参与者

- 主要参与者：ACT-001 开发者
- 支持参与者：无

## 触发

开发者在条目列表或详情上选择"影响定位"。

## 前置条件

- 应用已打开该项目（UC-010）；
- 目标条目存在。

## 最小保证

- 只读操作，任何失败不改变库内数据；
- 遍历有深度上限与环保护，不会无限展开。

## 成功保证

- 展示从目标条目出发、沿关系（考虑方向）可达的受影响条目集合，按类型
  分组（设计条目与 TASK-* 分开）；
- 清单中每项可跳转到对应条目详情；
- 同一数据下重复执行结果一致。

## 主流程

1. 开发者选择目标条目并执行影响定位；
2. 系统读取该项目关系集合；
3. 系统沿受影响方向做多跳遍历（可多跳，带深度上限；depends 无环由
   BR-007 在写入时保证，遍历另有环保护兜底）；
4. 系统汇总可达条目，按类型分组（设计条目 / TASK-*）；
5. 开发者查看清单，点击任一项跳转到条目详情（UC-011）。

## 备选流程

### A1 无下游关系

目标条目无出边（受影响方向）：显示"无受影响条目"的明确提示。

### A2 数据规模大

遍历结果超出展示上限：分页或分组折叠展示，性能目标见 NFR-002。

## 异常流程

### E1 读取失败

数据库读取错误：显示错误提示，不展示部分结果。

## 业务规则

- BR-007：depends 无环，为遍历安全的前提。

## 非功能要求

- NFR-002：目标数据规模下遍历与展示 ≤ 1 秒。

## 开放问题

- 遍历语义已在 03 领域模型定稿：从目标条目沿 derives/satisfies/depends
  的入边反向多跳闭包（"谁派生自我、谁满足我、谁依赖我"）；traces/relates
  不参与遍历，仅作上下文展示（DOM-003）。
