# mcp-bridge（独立可执行）

> 状态：草稿
> 组件：CMP-008
> 承载：UC-009、INT-003/005、ADR-005

## 责任

- 作为 stdio MCP Server 面向 MCP 客户端；作为 HTTP 客户端面向应用
  本地 API；
- 发现：读 `~/.relayharbor/runtime/bridge.json`（INT-005 格式）；
- 拉起：文件缺失或连接失败时启动应用进程并轮询就绪（时限见下），
  重读 bridge.json 后继续；
- 透传：双向转发，不改内容、不缓存业务数据；
- 令牌注入：上行请求自动附加当前令牌（客户端无感知）。

## 不负责

一切业务逻辑、数据缓存、凭据持久化（内存中仅当前 bridge.json 内容）。

## 公开接口

INT-003（对客户端）；消费 INT-002/INT-005。

## 关键规则（时限在此定案，UC-009 开放问题关闭）

- 就绪轮询：拉起后每 500ms 重读 bridge.json 并探测端口，上限 **15 秙**
  （覆盖冷启动 ≤3s 的 5 倍余量，NFR-003）；超时向客户端返回明确错误；
- 令牌失效（401）：自动走一次发现/拉起流程后重试原请求一次，仍失败
  才报 ERR_UNAUTHORIZED；
- 应用退出（连接拒绝）：同上自动恢复；恢复期间请求排队上限 1 条，
  其余快速失败。

## 状态与数据

仅内存转发状态与最近一次 bridge.json 快照；无磁盘写入。

## 错误处理

所有失败向 stdio 客户端返回结构化 MCP 错误（映射 api-contracts
错误码），绝不静默挂起（UC-009 最小保证）。

## 并发与一致性

单客户端单实例（每 MCP 客户端配置一个 bridge 进程）；请求串行或
低并发复用连接，无状态依赖。

## 可观测性

stderr 输出发现/拉起/重连事件（MCP stdio 约定 stdout 保留给协议），
供 Plugin 日志采集。

## 测试要点

- 三条恢复路径（缺文件/令牌失效/应用退出）；时限边界；透传保真。

## 开放问题

实现语言与打包方式（随 Plugin 分发约束）待 Plugin 侧联定时定，
不影响本契约。
