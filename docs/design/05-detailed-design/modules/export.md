# 导出（Markdown 文档集）

> 状态：草稿
> 组件：CMP-004（编排与格式）+ CMP-007（写盘）
> 承载：UC-016、FR-014、OQ-001、INT-006

## 责任

- services：取当前数据 → 交 domain/snapshot 的确定性格式化（类型固定序、
  编号排序、内容模板）→ 得到完整文件清单（路径 + 字节）；
- infra（SnapshotWriter）：写目标目录或打包 zip；原子性策略——先写
  临时目录，全部成功后 rename 到目标（目录形态）或直接产 zip（天然
  原子）；失败清理临时产物并报错。

## 不负责

导入（M2）；从导出物恢复数据库（导出是审查快照，非备份权威，
OQ-001/NFR-004）。

## 公开接口

INT-006（目录结构与确定性要求见 api-contracts.md）；ipc 命令
`export_markdown(project_id, scope?, target_path)`。

## 内部协作者

domain/snapshot（格式与排序规则的所有者，ADR-001 分层规则的典型应用：
换文件系统或换打包格式不改业务规则）、infra/runtime（路径与写盘）。

## 关键规则

- 确定性：同数据两次导出字节一致——排序、换行、时间戳格式（UTC、
  秒精度）全部由 snapshot 模块统一定义；
- 内容 = 当前修订 + 修订历史摘要（UC-016 开放问题已定案）；
- 失败不污染：目标已存在时策略为拒绝（提示用户更换路径），不合并、
  不覆盖；
- 大项目导出异步执行（ipc 返回任务句柄，进度事件推送），不阻塞 UI
  （NFR-002 备注）。

## 状态与数据

导出过程状态（进度）在内存任务表中，完成即清。

## 错误处理

路径不可写 / 磁盘满 / 部分写入失败：清理临时产物，返回明确错误与
已完成比例（UC-016 最小保证）。

## 并发与一致性

读快照于导出开始时点固定（单次取数）；导出期间的新写入不影响本次
产物（一致性 = 导出开始时的库快照）。

## 可观测性

导出开始/完成/失败与文件数入日志。

## 测试要点

- 确定性（同数据两次导出 diff 为空）；失败清理；含/不含各类型边界的
  结构断言。

## 开放问题

无。
