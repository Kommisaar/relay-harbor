## 布局（UI-019～021）

- 顶部：**全局单过滤框**（编号/标题关键词，同时作用于五列）——
  FR-011 原文「列内可按编号、标题过滤」的实用化解读（在看板内过滤，
  而非每列重复输入），语义不变，已在需求侧注记；
- 五列横排：待办 / 进行中 / 待验收 / 完成 / 已取消；列头 = 状态名 +
  计数（过滤后计数）；列等宽，超出窗口横向滚动；空列保留列头；
- 任务**基础卡片**（UI-020）：编号 + 标题 + 阻塞标记——被未完成
  depends 阻塞时显示「⛔ 被 TASK-XXX 阻塞」，来源编号可点击跳转其
  详情；阻塞来源完成后标记随刷新消失（BR-010 派生，只读呈现）。

```text
任务面板                    [过滤：编号/标题…]
┌ 待办 (3) ┐┌ 进行中 (2)┐┌ 待验收 (1)┐┌ 完成 (5)┐┌ 已取消 (1)┐
│ TASK-009 ││ TASK-007  ││ TASK-004  ││ …      ││ …        │
│ 卡片     ││ ⛔TASK-005││           ││        ││          │
└──────────┘└───────────┘└───────────┘└────────┘└──────────┘
 ← 横向滚动 →
```

## 数据

`get_task_board`（状态分组 + 阻塞派生标记）→
`["projects", id, "task-board"]`，与概览页阻塞提醒同源。

## 交互

- 只读：无拖拽、无状态迁移入口（FR-011 验收明确；迁移仅经 MCP）；
- 卡片点击 → 任务条目详情（TASK 也是条目）。

## 状态与边界

- 无任务：引导空态；
- 过滤无结果：各列计数 0 + 空列头；
- 加载：五列骨架卡片。

## 测试要点

列与任务状态一致；阻塞标记与 depends 数据一致、来源完成即消失；
过滤作用全列；无任何写交互控件。
