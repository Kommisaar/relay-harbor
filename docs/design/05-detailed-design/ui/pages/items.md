# 条目浏览页

> 状态：待确认
> 路由：`/projects/:id/items`
> 关联：UI-012～014、FR-009、UC-011、CMP-001

## 布局（UI-012/013/014）

- 顶部过滤工具条：状态过滤（全部/草稿/评审中/已确认/已取消/已替代）+
  关键词框（前端过滤标题/编号）+ 排序（编号升序默认 / 更新时间降序）；
- 内容：**手风琴分组**，13 种类型各一组，组头 = 类型名 + 计数 + 折叠
  箭头；仅渲染有条目的组（零计数类型不出现在列表，与概览页类型分布
  互补）；展开状态记入 UI 态，跨会话不要求记忆；
- 组内条目**标准行**：编号（等宽）+ 标题 + 状态徽章（UI-030）+ 当前
  修订号 + 最后更新相对时间。

```text
条目浏览        [状态▾] [关键词…] [排序▾]
┌ FR 功能需求 (42) ──────────────── ▾
│ FR-001  用户登录        [已确认] r3 · 2分钟前
│ FR-002  数据导出        [评审中] r2 · 1小时前
├ UC 用例 (18) ─────────────────── ▸
└ DOM 领域概念 (8) ──────────────── ▸
```

## 数据

`list_items`（类型/状态过滤参数）→ `["projects", id, "items", filters]`。
一次拉全量条目摘要（万级规模 NFR-002 已覆盖，前端分组），或按组惰性
加载——实现自选，不构成设计差异。

## 交互

- 点击行 → `/projects/:id/items/:code` 详情；
- 状态过滤与关键词同时生效（服务端过滤 + 前端过滤叠加）。

## 状态与边界

- 空项目/过滤无结果：空态提示（UI-031）；
- 加载：分组骨架屏。

## 测试要点

分组计数与实际一致；过滤组合生效；TASK 组在此页同样可浏览（任务
主视图是看板，此处为全类型完整性）。
