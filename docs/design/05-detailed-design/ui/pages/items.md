# 条目类型页（原条目浏览页）

> 状态：待确认
> 路由：`/projects/:id/items/type/:type`（15 类型各一页；`/projects/:id/items` 重定向首个类型）
> 关联：UI-012～014、FR-009、UC-011、CMP-001
>
> **2026-09-01 用户指令修订**：原「条目浏览页」13 类型手风琴聚合形态
> 取消——每个类型块扁平化为第二层侧栏独立子页面（类型固定常驻，
> 无条目的类型同样出现），聚合页不再存在。

## 布局（UI-012/013/014 修订）

- 页标题 = 类型编号（等宽）+ 类型名（如「FR 功能需求」）；
- 顶部过滤工具条（作用域收窄到单类型）：状态过滤（全部/草稿/评审中/
  已确认/已取消/已替代）+ 关键词框（前端过滤标题/编号）+ 排序
  （编号升序默认 / 更新时间降序）；
- 内容：该类型条目**标准行**平铺（UI-013）：编号（等宽）+ 标题 +
  状态徽章（UI-030）+ 当前修订号 + 最后更新相对时间；无分组、无折叠。

```text
FR 功能需求              [状态▾] [关键词…] [排序▾]
┌────────────────────────────────────────────┐
│ FR-001  用户登录        [已确认] r3 · 2分钟前
│ FR-002  数据导出        [评审中] r2 · 1小时前
└────────────────────────────────────────────┘
```

## 导航

- 第二层侧栏项目子导航固定 15 类型条目（概览 / FR…UI/MOD…TASK / 设计文档），
  置于概览与任务之间；当前类型页高亮；条目详情页按编号前缀
  （`ADR-002` → `ADR`）高亮所属类型。

## 数据

`list_items`（type + status 过滤参数）→ `["projects", id, "items", filters]`；
类型经路由参数走服务端过滤。

## 交互

- 点击行 → `/projects/:id/items/:code` 详情；
- 状态过滤与关键词同时生效（服务端过滤 + 前端过滤叠加）；
- `/projects/:id/items` → 重定向 `/projects/:id/items/type/FR`
  （首个类型，静态跳转）。

## 状态与边界

- 路由类型非法（不在 15 类型内）：空态提示（UI-031）；
- 该类型无条目 / 过滤无结果：空态提示（UI-031）；
- 加载：工具条常驻，骨架屏仅出现在列表区（2026-09-01 用户指令）。

## 测试要点

类型页仅含该类型条目；过滤组合生效；TASK 类型页同样可浏览（任务
主视图是任务面板，此处为全类型完整性）；空类型页可达且空态正确。
