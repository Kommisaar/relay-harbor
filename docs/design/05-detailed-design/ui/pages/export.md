# 导出面板页

> 状态：待确认
> 路由：`/projects/:id/export`
> 关联：UI-023、FR-014、NFR-002/004、UC-016、INT-006、CMP-007

## 布局（UI-023）

表单式单页，自上而下：

1. **范围**：单选「整项目 / 按类型」；按类型时 13 类多选（默认全选）；
2. **形式**：单选「目录 / zip」；
3. **目标路径**：系统目录选择器 + 路径展示；提示「目标已存在将拒绝
   覆盖」（INT-006 既有语义）；
4. **导出按钮**：提交后进入执行态——按钮禁用 + 进度条（异步进度事件，
   NFR-002 不阻塞界面）；
5. **结果条**：成功 = 完成摘要 + 「打开目录」动作；失败 = 原因 +
   已完成部分说明（UC-016 A1/E1），无误导性成功产物。

```text
导出 Markdown
范围   ○ 整项目  ○ 按类型 [☑FR][☑UC][☑DOM][☑TASK]…
形式   ○ 目录   ○ zip
路径   [D:\exports\relay-harbor…] [选择…]
       ⚠ 目标已存在将拒绝
       [ 导出 ]
       ████████████░░░ 68%
       ✓ 完成 [打开目录]
```

## 数据

`export_markdown(project_id, scope?, target_path)`（INT-006）+ 导出
进度事件；目录结构确定性规则见 modules/export.md（本文不重复）。

## 交互

- 全页唯一有「动作感」的页面，但写目标是文件系统快照，非业务库
  （OQ-001：导出物不是事实来源）；
- 执行中允许离开页面（后台继续，返回显示当前进度）。

## 状态与边界

- 项目为空：提示并中止（UC-016 A2 默认中止）；
- 范围筛选无匹配：提示（A3）；
- 目标不可写：失败结果条呈现原因（A1）。

## 测试要点

表单参数与 export_markdown 契约一致；进度事件驱动进度条；失败路径
提示完整；同数据两次导出入口一致（确定性由后端保障，UI 不加时间戳
类动态信息）。

## 全部项目导出（UI-033，2026-08-28 用户指令新增）

路由 `/export`（侧栏顶部「导出」全局位入口，2026-08-28 侧栏重构）：
表单结构同本文 UI-023，但无「范围」选择（恒为全部条目），仅 形式
（目录/zip）+ 目标路径 + 异步进度 + 结果条。目录形态按
`目标路径/项目名` 分子目录；zip 形态每项目一个压缩包。
